## The build

- **What I built:** Build me an analytics dashboard of issues that need to be fixed that surfaces the single most important insight first. Include one headline metric with a plain-language takeaway and a clear recommended next action. There should be at least three pages to this dashboard and one page should reference all the insights that are found. The first page should have the highlighted reference first but also list the next 3 insights in level of importance as well. Give the headline metric a line chart that provides data over the time periods of 1, 2, 4, 6, and 8 weeks. Make the chart interactive so when a hover over it the data will show for that period I want to change the name to Insights / Analytics I would like to be able to look at the trend information for each insight on the trends page, but I only want the trend information shown from the insight chosen. I.E. If I choose to view the trend from insight four, I only see insight four trend information. Be sure to label the start page so the user clearly understand the prepose of the dashboard. Make sure that navigation buttons are clearly marked. Please use an Asana theme. I need to make sure that each issue has a link to the insight and trend page and that the links are clearly marked as to where they are going. Also the trend page needs to have a link back to the insight page and that link needs to be clearly marked as well. Also please state on the main page what the fixes are for.

## Show & Swap read

_What a partner understood from your build with no verbal setup, their reaction is your first piece of product evidence._

- **What they understood immediately:** It’s meant to help someone quickly see what needs attention in their website analytics. The dashboard leads with a high bounce rate, explains what that means in plain language, and suggests a next step.
- **What confused them:** I wasn’t sure what kind of website or visitors the sample numbers represent, so I couldn’t tell whether a 62% bounce rate is especially concerning here. The date-range buttons also appear to change the metrics, but the chart itself stays the same, which made me wonder whether the ranges are fully connected.
- **The assumption they thought you were testing:** That people can understand and act on their analytics more easily when the dashboard puts one important insight and a recommended action first, instead of asking them to interpret a collection of charts on their own.
- **The gap between what you intended and what they read:** I intended the dashboard to make the most important issue obvious and help users decide what to do next. My coworker understood that purpose, so the main message came through. The gap is that I assumed the sample metric would feel meaningful on its own; without context about the website or a benchmark, they couldn’t judge how serious it was. The date filters also suggested the chart would update, but it didn’t, making the prototype feel less complete than I intended.
